## 📁 Project Structure

```
Robotics Society UC Merced/
├── backend/                  ← Django (Python) — API + WebSocket server
│   ├── api/                  ← Our custom app
│   │   ├── models.py         ← Database tables (User, Channel, Message, Announcement)
│   │   ├── views.py          ← REST API logic
│   │   ├── consumers.py      ← WebSocket handler (real-time chat)
│   │   ├── routing.py        ← WebSocket URL routes
│   │   ├── serializers.py    ← JSON conversion
│   │   ├── urls.py           ← REST API URL routes
│   │   └── admin.py          ← Django admin panel registration
│   ├── core/                 ← Django project config
│   │   ├── settings.py       ← All Django settings
│   │   ├── urls.py           ← Root URL config
│   │   └── asgi.py           ← ASGI entry point (HTTP + WebSocket)
│   ├── staticfiles/          ← Auto-generated by collectstatic — do not edit
│   ├── manage.py             ← Django CLI tool
│   └── db.sqlite3            ← Local database (auto-created)
│
├── src/                      ← React (JavaScript) — Frontend
│   ├── pages/                ← One file per page
│   │   ├── Home.jsx          ← Public homepage
│   │   ├── Portal.jsx        ← Members dashboard + real-time chat
│   │   ├── ProjectBattleBots.jsx
│   │   ├── ProjectRallyCart.jsx
│   │   └── ProjectRobotArm.jsx
│   ├── hooks/
│   │   └── useSocket.js      ← WebSocket connection hook
│   ├── assets/               ← Images, team photos, logo
│   ├── App.jsx               ← Route definitions
│   ├── Navbar.jsx            ← Navigation bar
│   └── index.css             ← All site styling
│
├── vite.config.js            ← Frontend build config + API/WebSocket proxy
└── package.json              ← JavaScript dependencies
```

> **How it works:** React runs on **port 5173** (what you see in the browser).
> Django runs on **port 8000** (the API + WebSocket server).
> Vite automatically proxies `/api`, `/admin`, and `/ws` from 5173 → 8000.
> You never need to worry about cross-origin issues in development.

## 🚀 First-Time Setup

Do this **once** after cloning the repo.

### Step 1 — Clone the repository

```bash
git clone https://github.com/Angel-A-V/Robotics-Society-UC-Merced.git
cd "Robotics Society UC Merced"
```

---

### Step 2 — Set up the Django backend

```bash
cd backend

# Create and activate virtual environment
python3 -m venv venv
source venv/bin/activate        # Mac / Linux
# venv\Scripts\activate         # Windows (use this instead)
```

You'll know it's active when you see `(venv)` at the start of your prompt.

Install **all** Python dependencies:

```bash
pip install django djangorestframework djangorestframework-simplejwt django-cors-headers channels daphne whitenoise
```

> ⚠️ **All seven packages are required.** The project uses:
> - `channels` + `daphne` for real-time WebSocket chat
> - `whitenoise` so Django admin CSS loads correctly through daphne

Apply database migrations (creates all the tables):

```bash
python manage.py migrate
```

Collect static files (makes Django admin CSS/JS work — **run this once**):

```bash
python manage.py collectstatic
```

Type `yes` when prompted.

---

### Step 3 — Set up the React frontend

Open a **new terminal** in the root folder (not inside `backend/`):

```bash
cd "Robotics Society UC Merced"
npm install
```

## ▶️ Starting the Project (Every Time You Work On It)

You need **two terminals open simultaneously**.

### Terminal 1 — Django backend

```bash
cd backend
source venv/bin/activate        # Mac / Linux
# venv\Scripts\activate         # Windows

daphne -p 8000 core.asgi:application
```

> ⚠️ **Always use `daphne`, NOT `python manage.py runserver`.**
> The project uses WebSockets for real-time chat. The built-in Django dev
> server does not support WebSockets. Daphne does.

✅ Success looks like:
```
Starting server at tcp:port=8000:interface=127.0.0.1
Listening on TCP address 127.0.0.1:8000
```

### Terminal 2 — React frontend

```bash
cd "Robotics Society UC Merced"
npm run dev
```

✅ Success looks like:
```
VITE ready in ...ms
➜  Local: http://localhost:5173/
```

Open **http://localhost:5173** in your browser.

## 👤 Creating the First Admin Account

The **first person to register** on a fresh database automatically becomes admin.

1. Make sure both servers are running
2. Go to `http://localhost:5173/register`
3. Register an account — you are now admin
4. Log in and go to `/portal` — you will see the **Admin Panel** tab

---

## 🔑 Role System

| Role | What they can do |
|------|-----------------|
| **pending** | Default after registering. Can view announcements and read chat. Cannot send messages. |
| **member** | Approved by admin. Can send messages and participate fully. |
| **admin** | Full access. Approve users, manage roles, post announcements, delete messages, access Django admin. |

Admins approve users from **Portal → Admin Panel → ✓ Approve**.

## 🛡️ Django Admin Access (`/admin`)

Django's admin panel at `http://127.0.0.1:8000/admin` is a separate system.
It requires `is_staff = True` on the user — just having `role = "admin"` on
the website is not enough by itself.

**This is handled automatically going forward** — when you promote someone
to admin through the portal, `is_staff` and `is_superuser` are set at the
same time.

**One-time fix for existing admin accounts** (only needed if your database
was created before this fix — i.e. you already have an admin account that
can't log into `/admin`):

```bash
cd backend
source venv/bin/activate
python manage.py shell
```

Then type these lines **one at a time**, pressing Enter after each:

```python
from api.models import User
```
```python
for u in User.objects.filter(role='admin'):
```
```python
    u.is_staff = True
```
```python
    u.is_superuser = True
```
```python
    u.save()
```
```python
    print(u.username)
```

Press **Enter twice** (blank line ends the loop). Then type:

```python
exit()
```

Restart daphne. You can now log into `http://127.0.0.1:8000/admin` with
the **same username and password** you use on the website.

## 💬 Setting Up the Chat

The portal has real-time Discord-style chat. After the backend is running:

**Create your first channel:**
1. Go to `http://127.0.0.1:8000/admin`
2. Log in with your admin credentials
3. Click **Channels** → **Add Channel**
4. Name: `general`, Description: `This is an overall chat` → Save
5. Refresh the portal — the channel appears in the sidebar and connects live

**How to test chat with multiple users:**
- Browser 1 (normal): log in as admin
- Browser 2 (Incognito/Private): log in as a member account
- Both go to Portal → Chat → #general
- Messages sent in one window appear instantly in the other

**Messages are saved permanently.** History loads every time you open a channel.

## 🛣️ Backend API Routes

Base URL: `http://127.0.0.1:8000`

All protected routes require the header:
```
Authorization: Bearer <your_access_token>
```
You get this token when you log in or register.

### 🔐 Auth

| Method | Route | Auth | Who | Description |
|--------|-------|------|-----|-------------|
| `POST` | `/api/auth/register` | ❌ | Anyone | Register. Returns JWT tokens. Body: `{ username, email, password, confirm_password }` |
| `POST` | `/api/auth/login` | ❌ | Anyone | Login. Returns `access` + `refresh`. Body: `{ username, password }` |
| `POST` | `/api/auth/refresh` | ❌ | Anyone | Get new access token. Body: `{ refresh }` |
| `GET`  | `/api/auth/me` | ✅ | Any user | Returns current user's data |

### 👥 User Management (Admin only)

| Method | Route | Description |
|--------|-------|-------------|
| `GET`  | `/api/auth/users` | List all users |
| `POST` | `/api/auth/users/<id>/approve` | Approve pending user (sets role to member) |
| `PUT`  | `/api/auth/users/<id>/role` | Change role. Body: `{ role }` — `pending` / `member` / `admin` |

### 📢 Announcements

| Method | Route | Who | Description |
|--------|-------|-----|-------------|
| `GET`    | `/api/announcements/` | Any user | List all announcements |
| `POST`   | `/api/announcements/create` | Admin | Create. Body: `{ title, content, is_pinned }` |
| `GET`    | `/api/announcements/<id>/` | Admin | Get one |
| `PUT`    | `/api/announcements/<id>/` | Admin | Edit |
| `DELETE` | `/api/announcements/<id>/` | Admin | Delete |

### 💬 Chat — REST (history + fallback)

| Method | Route | Who | Description |
|--------|-------|-----|-------------|
| `GET`    | `/api/chat/channels/` | Any user | List all channels |
| `GET`    | `/api/chat/channels/<id>/messages/` | Any user | Load message history |
| `POST`   | `/api/chat/channels/<id>/messages/send` | Members + Admins | Send message via REST |
| `DELETE` | `/api/chat/messages/<id>/delete` | Author or Admin | Soft-delete a message |

### ⚡ Chat — WebSocket (real-time)

| | URL | Description |
|-|-----|-------------|
| Connect | `ws://localhost:5173/ws/chat/<channel_id>/?token=<jwt>` | Opens real-time connection. Vite proxies this to daphne on port 8000. |

The server broadcasts to all connected users:
```json
{ "id": 1, "content": "hello", "username": "angel", "role": "admin", "created_at": "..." }
```

### 🛠️ Django Built-in

| URL | Description |
|-----|-------------|
| `http://127.0.0.1:8000/admin` | Django admin dashboard |

## ❓ Troubleshooting

**Django admin has no CSS / looks unstyled**
```bash
cd backend && source venv/bin/activate
python manage.py collectstatic    # type "yes"
daphne -p 8000 core.asgi:application
```

**Chat shows "Connecting..." forever**
- Make sure you're using `daphne`, NOT `manage.py runserver`
- Make sure at least one Channel exists in Django admin
- Try logging out and back in (JWT token may have expired)

**Chat doesn't show old messages when opening a channel**
- The history loads from the REST API — make sure daphne is responding
- Check the browser console (F12 → Console) for errors

**Missing Python packages**
```bash
source venv/bin/activate
pip install django djangorestframework djangorestframework-simplejwt django-cors-headers channels daphne whitenoise
```

**Missing JavaScript packages**
```bash
npm install
```

**403 on Django admin login**
- Make sure `CSRF_TRUSTED_ORIGINS` is in `settings.py`
- Restart daphne after any settings change

**Admin account can't log into `/admin`**
- Run the one-time shell fix in the Django Admin Access section above
- Password is the same as the website password

**Database errors / "table does not exist"**
```bash
python manage.py migrate
```
